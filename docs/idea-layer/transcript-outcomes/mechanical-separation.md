# Mechanical transcript separation v1

Run `python3 -m speechprefix.transcript_processing.mechanical INPUT.jsonl NEW_OUTPUT_DIR --id-field speech_id --text-field text` for the flattened long-speech view. Each UTF-8 JSONL record must contain a nonempty string ID and a string text in the named top-level fields; empty text is allowed. The parent of the output directory must exist, and the output directory must not exist. No source is changed. If processing fails, the directory is marked `INCOMPLETE`; discard or investigate its partial files before rerunning to a new directory. This tool does not select speakers, clean text, reconcile duplicates, or establish corpus eligibility. Turn-based records need an explicitly selected/prepared text field first.

The three JSONL files contain one row per input record and an ordered `units` array. Each row carries the source path, one-based input line, ID and field names, SHA-256 of the UTF-8 text, and rule version. Duplicate IDs remain distinguishable by source line. Each unit has zero-based, half-open **Unicode code point** offsets into the original text and its exact surface text. No normalization or case, punctuation, whitespace, or annotation cleaning is applied. Outputs are transcript outcomes, not features for the same event.

- **Words:** maximal runs of non-whitespace characters (Python Unicode whitespace). Punctuation stays attached, so `can't`, `word,`, and `a—b` remain intact. Whitespace is not a word; gaps between offsets retain its position in the input. This is a reproducible mechanical convention, not a linguistic tokenizer.
- **Sentences:** split on every literal `.` and omit the delimiter from each segment. Empty segments are retained, including for an empty input and after a trailing period. `"Dr. X 3.14..."` becomes `['Dr', ' X 3', '14', '', '', '']`; abbreviations, decimals and ellipses receive no special handling. Joining segments with `.` reconstructs the input, including whitespace and punctuation.
- **Characters:** one Unicode code point per unit, including whitespace and punctuation. A combining mark or multi-code-point emoji is multiple units, not a grapheme cluster. Concatenating units reconstructs the input.

Word offsets and the source text reconstruct each exact word and its intervening separators; character and sentence outputs independently reconstruct the entire input. These rules are provisional surface targets and do not establish semantic quality, reviewed labels, or readiness of all layers for training. Source text and artifacts may carry reuse restrictions and should remain local unless separately authorized.
